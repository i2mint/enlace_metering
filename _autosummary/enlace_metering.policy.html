enlace_metering.policy#

Access-gating policies — the enforcement half of metering (deny before spend).

Usage-based systems separate enforcement (may this call proceed?) from billing/recording (what did it cost?). The gate runs before the ledger ever sees the event: entitlement/quota checks are a distinct layer from the meter that records spend (see the package README for the research + sources). This module is that gate — and it is a strategy: whether to let a principal use a resource is a pure function GatePolicy = (GateRequest) -> Decision that a host plugs in, with a library of parameterized constructors for the common credit-based formulas.

Everything here is pure + dependency-free (no fastmcp, no storage engine): a policy reads usage through the small UsageQuery protocol (which UsageLedger implements) and returns a Decision. That keeps the formulas unit-testable against a dict and reusable outside any connector.

Progressive disclosure: default to unlimited() or a single credit_cap(); compose with require_all() / per_principal() for tiered plans (e.g. the owner unlimited, everyone else a monthly cap).

class enlace_metering.policy.GateRequest(principal, ledger, now, proposed_cost_usd=None, tool=None)[source]#

Bases: object

Everything a policy needs to decide one call.

ledger is the usage read-side (UsageQuery); now is injected (timezone-aware UTC) so policies are deterministic + testable; proposed_cost_usd is this call’s estimated cost when the host can estimate it (else None — the gate then blocks on already-accumulated usage, the “you’ve hit your limit” model); tool is the operation name (for logging / per-tool policies).

enlace_metering.policy.balance_gate(get_balance)[source]#

Deny when a principal’s prepaid balance can’t cover the call.

get_balance(principal) -> remaining_usd is host-supplied (a credit store). Denies if the balance is non-positive, or (when estimable) below the call’s proposed_cost_usd. This is the true prepaid-credits model — burn-down lives in the host’s balance store; this only gates.

enlace_metering.policy.credit_cap(usd_per_period, *, period='month')[source]#

Deny once spend in the current calendar period reaches usd_per_period.

The prepaid-credit / metered-cap formula: a principal gets usd_per_period of spend per calendar period (default monthly), resetting on the boundary. When the host supplies proposed_cost_usd the check is forward-looking (deny a call that would cross the cap); otherwise it denies the next call once already at/over the cap (“you’ve hit your limit”).

Return type:

Callable[[GateRequest], Decision]

enlace_metering.policy.per_call_cap(usd)[source]#

Deny a single call whose estimated cost exceeds usd.

Needs proposed_cost_usd (the host must estimate); a call with no estimate is allowed (nothing to compare). Pair with a period cap via require_all() to bound both the per-call blast radius and the cumulative spend.

Return type:

Callable[[GateRequest], Decision]

enlace_metering.policy.per_principal(policies, *, default=None)[source]#

Route to a per-principal policy (tiered plans): {email: policy, ...}.

default handles principals not in the map (e.g. owner unlimited, everyone else a cap: per_principal({owner: unlimited()}, default=credit_cap(10))). With no default, an unlisted principal is denied (deny-by-default).

Return type:

Callable[[GateRequest], Decision]

enlace_metering.policy.require_all(*policies)[source]#

Allow only if every policy allows; first denial wins (AND / most-restrictive).

E.g. require_all(per_call_cap(2), credit_cap(20)) — bound both a single call and the monthly total. With no policies, allows (vacuous truth).

Return type:

Callable[[GateRequest], Decision]

enlace_metering.policy.rolling_window_cap(usd, *, window)[source]#

Deny once spend in the trailing window reaches usd.

A sliding window (e.g. $5 per rolling 24h) rather than a calendar reset — smoother rate control. Forward-looking when proposed_cost_usd is given.

Return type:

Callable[[GateRequest], Decision]
