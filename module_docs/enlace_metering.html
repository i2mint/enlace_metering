enlace_metering

enlace_metering — usage tracking + credit/quota access-gating for enlace connectors.

The enlace platform’s “usage & access-policy” layer — the sibling of enlace_auth (identity) and enlace_connector (deploy). Three cleanly separated concerns (the research + sources are in the README):

  • policy — the gate (strategy): pure GatePolicy formulas (unlimited(), credit_cap(), rolling_window_cap(), …) that decide allow/deny before a call runs. Enforcement is a distinct layer from recording.

  • ledger — the meter (record): UsageLedger over any MutableMapping (a dol store in prod → grows to blob storage untouched).

  • middleware — the FastMCP glue (needs the [mcp] extra) tying identity → gate → write-ahead ledger, fail-closed.

The core (policy + ledger) is dependency-free; the middleware is imported lazily, so import enlace_metering never requires fastmcp.

class enlace_metering.Decision(allow: bool, reason: str = '', remaining_usd: float | None = None)[source]

A gate outcome. allow is the verdict; reason is a human-facing explanation (surfaced to the caller on denial, and useful as a remaining-budget note on approval). remaining_usd is set by cap policies when meaningful.

class enlace_metering.GateRequest(principal: str, ledger: UsageQuery, now: datetime, proposed_cost_usd: float | None = None, tool: str | None = None)[source]

Everything a policy needs to decide one call.

ledger is the usage read-side (UsageQuery); now is injected (timezone-aware UTC) so policies are deterministic + testable; proposed_cost_usd is this call’s estimated cost when the host can estimate it (else None — the gate then blocks on already-accumulated usage, the “you’ve hit your limit” model); tool is the operation name (for logging / per-tool policies).

class enlace_metering.UsageLedger(store: MutableMapping)[source]

Append/overwrite usage ledger over an injected MutableMapping.

record writes one entry keyed {principal}/{month}/{id}.json; the metering middleware calls it twice per call (write-ahead started then the done / error update) under the same id, so the store ends with the final entry (its cost_usd is what spend_since sums). Entries need at least principal, month (YYYY-MM), id, and — for costed calls — ts (ISO) and cost_usd.

class enlace_metering.UsageQuery(*args, **kwargs)[source]

The read side a policy needs: a principal’s spend / call-count since a time.

UsageLedger implements this; a test can pass any object with these two methods. since is timezone-aware UTC.

enlace_metering.balance_gate(get_balance: Callable[[str], float]) → Callable[[GateRequest], Decision][source]

Deny when a principal’s prepaid balance can’t cover the call.

get_balance(principal) -> remaining_usd is host-supplied (a credit store). Denies if the balance is non-positive, or (when estimable) below the call’s proposed_cost_usd. This is the true prepaid-credits model — burn-down lives in the host’s balance store; this only gates.

enlace_metering.call_count_cap(max_calls: int, *, period: str = 'day') → Callable[[GateRequest], Decision][source]

Deny once the principal has made max_calls in the current calendar period.

A count-based quota (no cost model needed) — useful for free/rate-limited tools.

enlace_metering.credit_cap(usd_per_period: float, *, period: str = 'month') → Callable[[GateRequest], Decision][source]

Deny once spend in the current calendar period reaches usd_per_period.

The prepaid-credit / metered-cap formula: a principal gets usd_per_period of spend per calendar period (default monthly), resetting on the boundary. When the host supplies proposed_cost_usd the check is forward-looking (deny a call that would cross the cap); otherwise it denies the next call once already at/over the cap (“you’ve hit your limit”).

enlace_metering.per_call_cap(usd: float) → Callable[[GateRequest], Decision][source]

Deny a single call whose estimated cost exceeds usd.

Needs proposed_cost_usd (the host must estimate); a call with no estimate is allowed (nothing to compare). Pair with a period cap via require_all() to bound both the per-call blast radius and the cumulative spend.

enlace_metering.per_principal(policies: Mapping[str, Callable[[GateRequest], Decision]], *, default: Callable[[GateRequest], Decision] | None = None) → Callable[[GateRequest], Decision][source]

Route to a per-principal policy (tiered plans): {email: policy, ...}.

default handles principals not in the map (e.g. owner unlimited, everyone else a cap: per_principal({owner: unlimited()}, default=credit_cap(10))). With no default, an unlisted principal is denied (deny-by-default).

enlace_metering.require_all(*policies: Callable[[GateRequest], Decision]) → Callable[[GateRequest], Decision][source]

Allow only if every policy allows; first denial wins (AND / most-restrictive).

E.g. require_all(per_call_cap(2), credit_cap(20)) — bound both a single call and the monthly total. With no policies, allows (vacuous truth).

enlace_metering.rolling_window_cap(usd: float, *, window: timedelta) → Callable[[GateRequest], Decision][source]

Deny once spend in the trailing window reaches usd.

A sliding window (e.g. $5 per rolling 24h) rather than a calendar reset — smoother rate control. Forward-looking when proposed_cost_usd is given.

enlace_metering.safe_key_component(value: str, *, what: str = 'key') → str[source]

A traversal-safe key component: reject empty, separators, ./.., NUL.

The ledger key is {principal}/{month}/{id}.json; every component is caller-influenced (the id embeds the tool name), so every component is checked. what names the component in the error message.

enlace_metering.safe_principal(principal: str) → str[source]

A traversal-safe, lowercased key component for a principal (email / sub).

Rejects empty, path-separator, ./.., and NUL so a hostile identity can’t escape its ledger prefix. Identity is case-insensitive (enlace_auth mints sub = email), so this lowercases too.

enlace_metering.unlimited() → Callable[[GateRequest], Decision][source]

Always allow — the meter still records, but nothing is gated (e.g. the owner).
